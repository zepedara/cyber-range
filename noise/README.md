# Noise engine

Spec §7.1 states the rule this directory exists to satisfy:

> Zeek creates a protocol log only when it observes that protocol. Every log type the range
> intends to be hunted must be generated by the noise engine. This is a hard requirement,
> not a realism nicety.

Driving protocols by hand does not satisfy it. On 2026-08-16 the log contract read 28 of 35
after a manual pass, then fell back to 19 of 35 the moment Zeek restarted and recreated
`/nsm/zeek/logs/current`. Anything the range wants hunted has to be produced continuously,
by something that survives a restart.

Both generators randomise every run. A perfectly periodic beacon is itself an unrealistic
signature, and a range that emits one trains analysts on the wrong instinct.

## `windows/domain_noise.ps1`

Deployed to `C:\Windows\Temp\domain_noise.ps1` on WS01, WS02, FS01 and SQL01, driven by the
scheduled task `RangeDomainNoise` (every 4 minutes, SYSTEM, highest privileges).

Produces `kerberos`, `ldap`, `smb_mapping`, `smb_files`, `dce_rpc`, `rdp`, `files`, `pe`,
`http` and `ssl`.

Two details that are easy to get wrong:

- **RDP needs a real X.224 Connection Request.** A bare TCP connect to 3389 produces no
  `rdp.log` at all — Zeek only recognises the session once the TPKT/X.224 CR crosses the
  wire, so the script writes those bytes itself.
- **PE transfer uses stock signed Windows binaries** (`notepad.exe`, `net.exe`, …) copied
  over SMB. Nothing malicious ever runs on the range.

Deploy with `scp`, not `smbclient`: SMB inbound is filtered on WS01/WS02/SQL01, and only
FS01 accepts a `C$` connection.

## `containers/rangenoise.sh`

Runs on cthost01 as `rangenoise.service`, looping on a randomised 45–135 s interval across
`wk01 wk02 wk03 app01 web01`. Produces `mysql` attempts, `syslog` and TLS.

## Deploying

```sh
# Windows half - scp, because SMB inbound is filtered on most guests
scp domain_noise.ps1 Administrator@10.31.20.100:C:/Windows/Temp/domain_noise.ps1
ssh Administrator@10.31.20.100 'schtasks /create /tn "RangeDomainNoise" \
  /tr "powershell -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File C:\Windows\Temp\domain_noise.ps1" \
  /sc minute /mo 4 /ru SYSTEM /rl HIGHEST /f'

# Container half
scp rangenoise.sh cthost01:/usr/local/sbin/rangenoise.sh
ssh cthost01 'systemctl enable --now rangenoise.service'
```

Each host writes `C:\Windows\Temp\domain_noise.log` so you can confirm a guest is actually
generating rather than merely scheduled.

## Verifying

Count the contract on so01. Note that `sudo wc -l < file` performs the redirect as the
*calling* user, who cannot read `/nsm/zeek/logs/current` — it silently reports 0 and has
produced false "the logs are empty" readings more than once. Let sudo do the read:

```sh
sudo bash -c 'wc -l < /nsm/zeek/logs/current/kerberos.log'
```
